# 개념 설명 (퍼블리셔 눈높이)

## 설명 원칙

1. **이미 아는 것에 연결한다.** HTML/CSS/jQuery 경험과 비교해서 설명한다.
   - 예: "props는 HTML 속성(attribute)과 같다. `<img src>`처럼 바깥에서 값을 넘긴다."
   - 예: "useEffect는 jQuery의 `$(document).ready()` + 값이 바뀔 때 다시 실행되는 것"
2. **코드 먼저, 설명은 짧게.** 10줄 이하 예제 → 3~5문장 설명 → 흔한 실수 1개.
3. **왜 필요한지**를 반드시 포함한다. (퍼블리싱만 할 때는 없던 문제가 무엇인지)
4. 용어는 영어 원어를 괄호로 병기한다. 예: 상태(state), 렌더링(rendering)
5. 한 번에 하나의 개념만. 관련 개념은 마지막에 "다음에 볼 것"으로 이름만 적는다.
6. 이 프로젝트 코드에 해당 개념이 쓰인 곳이 있으면 `파일:줄` 로 가리킨다.

## 자주 나오는 질문 매핑

| 질문                 | 연결할 기존 지식                                                           |
| -------------------- | -------------------------------------------------------------------------- |
| 컴포넌트가 뭐야      | 반복 사용하는 HTML 조각 + 그에 딸린 CSS·동작을 한 묶음으로                 |
| props / state        | props = HTML 속성, state = 그 요소가 스스로 기억하는 값 (체크박스 checked) |
| JSX                  | HTML처럼 생긴 JS. `class`→`className` 되는 이유는 JS 안이라서              |
| useState             | 값이 바뀌면 화면도 자동으로 다시 그려지는 변수                             |
| useEffect            | 화면이 그려진 뒤 할 일 (fetch, 이벤트 등록). `ready()` 와 비교             |
| 빌드가 뭐야          | SCSS 컴파일처럼 TS/JSX를 브라우저가 아는 JS로 변환 + 파일 합치기           |
| TypeScript 타입      | props에 어떤 값이 들어오는지 미리 적어두는 설명서. 오타를 빌드 전에 잡음   |
| CSS Modules          | 클래스명 충돌을 파일 단위로 자동 방지. BEM의 block 역할을 파일이 함        |
| 가상 DOM             | jQuery로 직접 `.html()` 갈아끼우던 것을 React가 바뀐 부분만 계산해서 해줌  |
| key                  | `map`으로 반복할 때 React가 어느 항목이 바뀌었는지 알아보는 이름표         |
| 비동기 / async-await | ajax 콜백을 위에서 아래로 읽히게 쓰는 문법                                 |
