# 학습형 코드 리뷰

목적은 고치는 것이 아니라 **다음에 스스로 더 잘 쓰게** 하는 것이다.

## 1. 대상

- 지정 파일, 없으면 `git diff` (git이 없으면 최근 수정된 파일)
- 전체를 먼저 읽고 **잘한 점 1~2개**를 먼저 찾는다. 퍼블리셔 강점(마크업, 스타일 구조)은 꼭 인정한다.

## 2. 리뷰 관점 (우선순위 순)

1. **동작 오류** — 렌더 안 됨, 무한 루프(useEffect 의존성), 상태 직접 변경(mutate), key 누락
2. **React 사고방식** — DOM 직접 조작(`document.querySelector`) 대신 state, jQuery식 패턴 잔재
3. **타입** — `any` 사용, props 타입 누락, 옵셔널 처리
4. **접근성·시맨틱** — `/a11y-check` 기준 중 높음만
5. **스타일 규칙** — `/css-guide` 위반 (하드코딩 색, 전역 스타일 오염)
6. **구조** — 너무 큰 컴포넌트(150줄 이상), 반복 코드, 네이밍

## 3. 코멘트 형식

항목당:

```
### [관점] 한 줄 제목   (파일:줄)

**현재:**
(코드 3~8줄)

**제안:**
(코드)

**왜:** 1~3문장. 퍼블리싱 경험에 빗대어 설명.
**심각도:** 반드시 / 권장 / 취향
```

- 최대 7개. 더 있으면 "그 외"로 한 줄씩만.
- "반드시"는 동작 오류·접근성 높음만.
- 같은 실수가 여러 곳이면 한 번만 설명하고 위치만 나열.

## 4. 마무리

- **이번 리뷰의 핵심 개념 1개**를 `/explain` 형식으로 짧게 정리한다. (예: "useEffect 의존성 배열")
- 사용자가 "고쳐줘" 하기 전에는 코드를 수정하지 않는다.
- 고치게 되면 "반드시" → "권장" 순으로, 한 항목씩 diff를 보여주며 진행한다.
